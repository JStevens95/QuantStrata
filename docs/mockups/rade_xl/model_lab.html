Gradient-boosted decision trees

tier 1 xgboost models/xgb_tabular

A boosted tree ensemble builds its prediction one small tree at a time. Each new tree is fitted not to the target but to the error left over by every tree before it, so the ensemble descends the loss surface in function space rather than parameter space. The result is a sum of hundreds of shallow, piecewise-constant functions.

Because every split is an axis-aligned threshold on one feature, the model is naturally good at interactions and sharp regime changes and naturally bad at smooth extrapolation. It never predicts a value outside the range it saw in training.

observed true generating function xgb_tabular fit
Notice the staircase. Every flat segment is a leaf of the ensemble. This is the single most useful intuition about tree models: they partition the input space into boxes and predict a constant inside each box. Increase max_depth and the boxes get smaller; increase n_estimators and the steps get finer and smoother.
Trade-offs

Reach for it when

  • Features are heterogeneous and tabular — mixed scales, mixed units, some categorical.
  • You expect threshold effects: "vol above 18 behaves differently".
  • You have thousands, not millions, of rows.
  • You need a strong baseline in minutes, with almost no preprocessing.
  • You want per-feature attribution that a desk head will accept.

Avoid it when

  • The relationship is genuinely smooth and you must extrapolate beyond the training range.
  • Inputs are sequential and order matters — use lstm_tabular.
  • Observations are coupled through a known structure — use hybrid_gnn_rnn.
  • You need calibrated uncertainty rather than a point estimate.
