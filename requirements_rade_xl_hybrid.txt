# Dependencies for the flagship hybrid GNN-RNN model.
#
# Model packages declare their own requirements.  That is the point of
# `models/*` being plugins: a host running a gradient-boosted model should not
# install this model's linear algebra, and this model should not be limited to
# what the framework core is willing to depend on.
#
# Install alongside the base and Torch requirements:
#   .venv/bin/python -m pip install -r requirements_rade_xl.txt \
#                                  -r requirements_rade_xl_torch.txt \
#                                  -r requirements_rade_xl_hybrid.txt

# Column-pivoted QR, for basis selection.
#
# This is the one third-party numerical routine the model does not
# reimplement, and the line is drawn deliberately.
#
# The attribute encoder and the instrument graph are hand-rolled in NumPy
# because their *fitted state* has to be saved.  Using scikit-learn there
# would mean pickling an estimator into every bundle, which pins a saved model
# to the library version that wrote it -- the exact fragility that
# `HybridState` exists to remove.
#
# Basis selection saves nothing.  It consumes a P&L matrix and returns a list
# of instrument identifiers, so no third-party object reaches a bundle and the
# objection does not apply.
#
# What does apply is that its output is a *discrete* choice.  Where the graph
# can absorb a last-bit difference in an edge weight, a last-bit difference in
# a QR pivot selects a different instrument and changes every number
# downstream -- there is no tolerance to fall back on.  NumPy has no pivoting
# QR, and hand-rolling one that matches LAPACK's pivot sequence on near-ties
# is a much larger risk than the dependency.
#
# The rank step needs nothing beyond NumPy's SVD, so scikit-learn is not
# required despite the baseline having used its PCA.
scipy>=1.11
